## Skill Loading

Before editing files for a substantial task:

- Run `bunx @tanstack/intent@latest list` from the workspace root to see available local skills.
- If a listed skill matches the task, run `bunx @tanstack/intent@latest load <package>#<skill>` before changing files.
- Use the loaded `SKILL.md` guidance while making the change.
- Monorepos: when working across packages, run the skill check from the workspace root and prefer the local skill for the package being changed.
- Multiple matches: prefer the most specific local skill for the package or concern you are changing; load additional skills only when the task spans multiple packages or concerns.

## Project Structure

TanStack Start conventions (see the `start-core`, `router-core`, and `router-plugin` intent skills for details):

- `src/routes/` — file-based routing. File path maps to URL path (e.g. `routes/users/$id.tsx` → `/users/$id`). Server API endpoints can live in the same file via the `server.handlers` property on `createFileRoute`, or as their own route file. Folder structure mirrors the URL for nesting:
  - `posts/route.tsx` — layout route for `/posts` and its children (the `routeToken`, configurable). Must render `<Outlet />` where children appear.
  - `posts/index.tsx` — `/posts` exact (the `indexToken`, configurable).
  - `posts/$postId.tsx` — `/posts/$postId` (dynamic segment). `$.tsx` is a splat/catch-all.
  - Pathless layout routes — prefix a segment with `_` (e.g. `_authenticated.tsx` wrapping `_authenticated/dashboard.tsx`) to wrap children in shared logic/UI (auth guards, etc.) without adding a URL segment.
  - Route groups — wrap a segment name in parentheses (e.g. `(marketing)/about.tsx`) to organize files without adding a URL segment or a layout wrapper. Purely organizational, unlike pathless layout routes.
  - Literal dots in a filename (e.g. for `/sitemap.xml`) must be escaped: `sitemap[.]xml.ts`.
- `src/routeTree.gen.ts` — generated by the router plugin. Never hand-edit.
- `src/router.tsx` — the `getRouter()` factory.
- `src/routes/__root.tsx` — root route and document shell (`HeadContent`, `Outlet`, `Scripts`).
- `src/lib/` — server-boundary code, split by suffix:
  - `*.functions.ts` — `createServerFn` RPC wrappers. Safe to import from client or server code.
  - `*.server.ts` — server-only helpers (DB queries, third-party API clients, secrets). Only imported by the matching `.functions.ts` file.
  - `utils.ts` — shared client-safe utilities (e.g. `cn`).
- `src/components/ui/` — shadcn/ui components (managed via the `shadcn` CLI, see `components.json`).

Loaders (the `loader` option on a route) are isomorphic — they run on both client and server. Never put secrets, DB access, or other server-only logic directly in a loader; call a `*.functions.ts` server function instead.
